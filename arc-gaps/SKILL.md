# arc-gaps 漏洞清单

> 核心信条：**漏洞只记一处，才数得清、补得完。**

每课题一份 `gaps.md`，是 arc 系列漏洞的唯一记录处。概念问答与答题对局自动往里追加，本 skill 负责手动补、改、删，以及把旧格式的漏洞行迁进来。

## 铁律

1. **只动清单**：写操作只有两类：增改删 `gaps.md` 条目；用户同意迁移后删掉旧文件里的漏洞行。不改 `concepts.md` 状态，不出题，不讲解概念。
2. **格式唯一**：落点、条目格式、来源取值一律以 `assets/gap-format.md` 为准。
3. **改删要点名**：只改写、删除用户点名的条目，动手前把原行贴出来确认；不顺手整理别的条目，不重排。
4. **迁移先问**：发现旧漏洞行，先列出来问用户，同意才导入并删旧行。
5. **编号不编**：`[D-xxx]` 必须能在课题 `concepts.md` 找到；对不上就省略，不现编 id。

## 流程

### 1. 定课题

用选择题提问工具确认课题，候选为有 `concepts.md`、`drills/` 或 `concept-sessions/` 的课题夹；都没有就提示先用 `/arc-distill` 建概念清单，然后停。读该课题 `gaps.md`，不存在就记下「待创建」，第一次写入时按头部模板建。

### 2. 迁移旧漏洞行

在该课题 `drills/*.md` 与 `concept-sessions/*.md` 里找旧格式的 `- 漏洞：` 行。有就按 `assets/migrate.md` 处理，没有就跳过本步。

### 3. 问要补什么

问用户这次要补的漏洞是什么；用户也可以说要改写或删除哪条。

- **新增**：
  1. 描述整理成一句话，说清错在哪或缺了什么，用户原话能用就用原话。
  2. 到 `concepts.md` 找对得上的概念，用选择题让用户确认 id，带一个「不对应任何概念」选项；没有候选就直接省略 id。
  3. 日期写今天，来源写 `手动`，不写原文件，追加到清单末尾。
- **改写**：用户点名哪条、改描述还是改 id；贴出原行和改后的行确认后替换。来源、日期、原文件不改。
- **删除**：贴出原行确认后删。

每处理完一条就问「还有要补的吗」，用户说没有了再往下。

### 4. 汇报并停止

列出本次迁入几条、新增几条、改写几条、删除几条，贴出新增与改写后的行，给出清单路径。提示可用 `/arc-examiner` 说「随便出」针对漏洞出题，想看进度可运行 `/arc-dashboard`。到此必须停。

## 注意

- 用户在对话里说的漏洞直接记；不用像问答、对局那样让用户先写进文件。
