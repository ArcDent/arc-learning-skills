# arc-concept-quiz 概念问答

> 核心信条：**能用自己的话说清核心，就算懂。**

一批题一次写进对局文件，学生答完一次交；当场通过进「待复验」，隔天复验通过才算掌握。

## 铁律

1. **只考清单内概念**：概念与批改基准一律来自课题夹 `concepts.md` 条目。用户点名清单外概念就提示先用 `/arc-distill` 凝练，本 skill 不现场编基准。
2. **先答后讲**：学生作答前不讲；答错或说不会，就把对的理解讲清楚，材料原文直接贴进文件。本 skill 只讲概念，解题是 arc-socratic-drill 的事。
3. **状态回写必做**：概念状态只由本 skill 改。状态取值与写法以 `arc-distill/assets/concept-format.md`（与本 skill 同级目录）为准。登记表只追加，绝不覆盖。
4. **没过要讲清错在哪**：只有实质误解或核心点缺失才判没过；判没过必须写明错在哪、为什么，并给出对的说法。
5. **一次只等一批**：文件里任何时刻只有一批题在等作答，首答或订正。一次只推进一场概念问答，与解题对局可并行，互不干扰。

## 核心点与批改口径

- **核心点**：这个概念最关键的那一条。出题时现场认：定义行说的那件事优先，其次是带（作业 x.y）标注或进了作业对照表的要点；⚠ 重测时，核心点就是上次误解所在的那条。
- **一题一点**：一题只考 1 个核心点，最多 2 个紧密相关的，学生 2–5 行能答完，约 3 分钟。其余要点这次不考，也不扣。
- **只批题面**：批改只针对题面实际问到的内容，题面引不出来的要点不扣。
- **过与没过**：核心理解对就判过。笔误、等价写法、约定不同但前后自洽都判过，在结论里附一行注。
  - 笔误：同一份回答里别处用对了，或学生自己改回来的符号、下标、因子、等号与不等号之类的错。
  - 等价写法：数学上等价的式子，换个说法意思不变，与课程约定不同但前后自洽。
- **结论要短**：结论先行，不超过 5 行，不逐条罗列每个要点的对错。
- **同类小错**：同一类小错一场里出现两次以上，终场点名一次作薄弱点，各题照常判过。

## 文件约定

- **对局文件与登记**：对局文件落点、模板、状态标记、登记字段、问法库，见 `assets/session-format.md`。

## 流程

### 1. 开场

1. 用选择题提问工具确认课题，候选为存在 `concepts.md` 的课题夹；都没有就提示先用 `/arc-distill` 凝练，然后停。
2. 查该课题 `concept-sessions/` 有没有首行 `arc-concept: open` 的旧场。有就问用户：续做（转第 5 步续场）还是作废。作废时首行改 `done`，文件末尾写「- 结果：中止于第 N 批，未回写清单」，不追加登记。
3. 建对局文件，对话里告知文件路径，进第 2 步出第 1 批。

**完成判据**：对局文件已建。

### 2. 组批出题

1. 扫 `concepts.md` 全部 `待复验 @ 日期` 条目：日期早于今天的进本批复验；日期是今天的，在本批开头写「当日记录，顺延至下场：{id 列表}」，状态不动。
2. 定本批题目：默认 5 题一批，用户点名数量就照办。到期复验优先占位，超出的留到下一批；剩下的位置给用户点名的概念，没点名就从 ⚠ 与 ☐ 条目里选：⚠ 优先于 ☐，同优先级沿依赖链先补前置。
3. 每题按「一题一点」从问法库抽 1 型设问，问法库见 `assets/session-format.md`。复验题与新题一样短，不预告上次的回答内容，防止学生凭记忆复述措辞而非理解。⚠ 重测针对上次误解设问。
4. 本批题目一次写进文件，题头标明新题、复验还是 ⚠ 重测。

**完成判据**：本批题目全部写进文件，在等回答。

### 3. 批改与订正

学生说「回答好了」，含「写完了」「答完了」等变体，读本批全部回答，逐题按「核心点与批改口径」写结论：

- **过**：新题与 ⚠ 重测记 `待复验 @ 今天`，复验题记 ☑。
- **没过，新题或 ⚠ 重测**：在该题写一次订正。差得不远，就指出错在哪，并贴出材料原文；差得远，或学生写了「不会」「讲给我听」，就直接讲清对的理解，不超过 8 行，同样贴原文。原文取 `concepts.md` 条目的原文字段，或 notes 里对应锚点附近不超过 10 行。订正末尾留一个复述或小变式问题，学生一两句话能答完。
- **没过，复验**：订正处只写讲解，不留问题；状态当场退回 ⚠，结论里写明误解。
- **跳过**：学生写「跳过」的题记「跳过」，状态不动；学生确认这条要点不考，可删掉 `concepts.md` 里对应的要点行。

有订正时，等学生把本批订正一次写完、再说「回答好了」：订正过记 `待复验 @ 今天`；订正没过记 ⚠，订正结论里写明误解：错在哪条要点、为什么。每个概念最多交 2 次，首答一次、订正一次；学生要求才再给一次。

本批状态全部定下后逐个回写 `concepts.md`。

**完成判据**：本批每题状态已定，并已回写 `concepts.md`。订正还在等回答时，本步未完成。

### 4. 终场

1. 问学生要不要「再来一批」。学生说要，回第 2 步，新批写在同一文件「第 N 批」下；学生说不要，或说过「结束」，往下收尾。
2. 对局文件写终场小结，首行改 `done`。
3. `.local/quiz-index.jsonl` 追加本场记录。
4. 汇报：过几个、⚠ 几个、跳过几个、复验结果、清单当前分布，同类小错点名一次。提示薄弱概念可再开一场，想看进度可运行 `/arc-dashboard`。到此必须停。

### 5. 续场

触发「继续概念问答」→ 找 `arc-concept: open` 的最新一场 → 读整个文件，重点最后一批，含订正 → 从在等回答的那一批继续。不存在 open 场时直接说明。

## 注意

- **与 arc-socratic-drill 的边界**：两套对局文件隔离、状态标记隔离，可并行推进。本 skill 不解计算题，drill 不考概念解释，也不改概念状态。
- **对话只报状态**：结论只写进文件，对话里报一句，如「第 1 批：3 题过，2 题待订正」；在等回答时末尾提醒「写完了回复回答好了」。
- **登记**：字段见 `assets/session-format.md`，旧记录里的 `followup_failed` 照常保留。
- 学生在回答区写的内容才算作答。对话里口头补充的，让学生写进文件再算数。
